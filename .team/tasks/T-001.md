## Objective

Establish the foundational architecture, system boundaries, shared TypeScript domain types, Supabase RLS contracts, and Gemini 2.5 Flash API schemas for Zankai Orbit to enable safe parallel development across Frontend, Backend, and Data specialists.

## Requirements

1. **System Boundaries & Architecture (`.team/ARCHITECTURE.md`):**
   - Document module boundaries: Next.js 15 App Router layout, page routing, server vs. client component boundaries.
   - Specify Supabase client architecture for Next.js (browser client, server client, route handler client) using `@supabase/ssr` / `@supabase/supabase-js`.
   - Specify client-side state architecture using Zustand for active board selection, drag & drop column/task state, task detail drawer state, and floating Pomodoro timer state.
   - Specify Google Gemini 2.5 Flash integration via `@google/genai` with strict structured JSON output schemas for Prompt-to-Board and Ask-Orbit task breakdown.
2. **Shared TypeScript Contracts (`src/types/`):**
   - Define core entity types: `Profile`, `Board`, `Column`, `Task`, `ChecklistItem`, `FocusSession`, `Priority = 'low' | 'medium' | 'high'`, `Tier = 'free' | 'pro'`.
   - Define API request & response types: `GenerateBoardRequest`, `GenerateBoardResponse`, `BreakdownTaskRequest`, `BreakdownTaskResponse`.
   - Define Kanban view models and drag-and-drop event payloads compatible with `@hello-pangea/dnd`.
   - Define floating timer states (`idle` | `running` | `paused` | `completed`) and focus session payloads.
3. **Architecture Decision Record (`.team/decisions/`):**
   - Author `ADR-001-stack-contracts-and-ai-architecture.md` detailing the choice of Supabase RLS policies, Gemini structured outputs with `@google/genai`, and Zustand store boundaries.
4. **Tone & Constraints:**
   - Adhere strictly to the consumer-first constraint: no developer terminology in user-facing types or client contracts.
