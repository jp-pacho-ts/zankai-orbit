## Objective

Build the consumer-facing authentication dialog with email magic link and Google/GitHub OAuth options, wire user profile dropdown in top navigation, connect real auth state lifecycle in Zustand, and ensure seamless hydration and sign-out cleanup.

## Requirements

1. **Consumer Auth Dialog (`src/components/auth/auth-modal.tsx`):**
   - Accessible, sleek modal matching canonical dark/light Montserrat design.
   - Tabs or simple toggle for "Sign In" and "Sign Up".
   - Support Email Magic Link (or passwordless email) and OAuth (Google, GitHub).
   - Friendly validation states, loading spinners, and clear consumer language (no technical jargon).
2. **Top Navigation User Menu (`src/components/nav/top-nav.tsx`):**
   - When unauthenticated: display "Sign In" button opening the Auth Modal.
   - When authenticated: show real user avatar, display name, email, tier badge ("Free Plan"), and a dropdown menu with "Account Settings" and "Sign Out".
3. **Store Auth Lifecycle & State Sync (`src/stores/`):**
   - Subscribe to Supabase `onAuthStateChange`.
   - On sign-in: hydrate user's boards and tasks from Supabase into `board-store`.
   - On sign-out: purge board tasks, timer state, and detail drawer back to fresh preview mode.
4. **Verification:**
   - Run `node --test tests/t-006-workflows.test.mjs`.
   - Run `npx tsc --noEmit` and `npm run build`.

## Acceptance criteria

- [ ] Auth dialog renders with Montserrat typography, theme support, and validation.
- [ ] Top nav switches seamlessly between "Sign In" button and user profile dropdown.
- [ ] User sign-in triggers board hydration; sign-out cleanly purges store state.
- [ ] Existing workflow tests continue passing.
- [ ] Build and TypeScript check pass cleanly.
