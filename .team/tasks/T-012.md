## Objective

Extend Supabase database triggers to idempotently provision a user profile and default starter board upon new user registration in `auth.users`, and provide typed client auth helpers in accordance with ADR-002.

## Requirements

1. **Idempotent Auth Onboarding Trigger (`supabase/migrations/`):**
   - Create an incremental migration `supabase/migrations/20261011000000_auth_onboarding_starter_board.sql`.
   - Extend `handle_new_user()` / `on_auth_user_created`:
     - Inserts a row into `public.profiles` (`id = NEW.id`, `email = NEW.email`, `display_name = COALESCE(NEW.raw_user_meta_data->>'full_name', split_part(NEW.email, '@', 1))`, default `tier = 'free'`) using `ON CONFLICT (id) DO NOTHING`.
     - Automatically creates one initial starter board ("My First Orbit") with default columns and a welcome task for the new user, ensuring no duplicates on repeated trigger events.
2. **Client Auth Helpers (`src/lib/supabase/auth.ts`):**
   - Provide client-side auth helpers for `signInWithOtp`, `signInWithOAuth`, `signOut`, `getUserProfile`, and `onAuthStateChange`.
   - Export typed helpers from `src/lib/supabase/index.ts`.
3. **RLS Verification:**
   - Confirm RLS policies on all tables (`profiles`, `boards`, `columns`, `tasks`, `checklist_items`, `focus_sessions`) strictly restrict access to `auth.uid() = user_id`.
4. **Verification:**
   - Run `npx tsc --noEmit` to verify type safety.
   - Run `npm run build` to confirm compilation.

## Acceptance criteria

- [ ] New migration `supabase/migrations/20261011000000_auth_onboarding_starter_board.sql` creates idempotent profile and starter board creation.
- [ ] Client auth utilities in `src/lib/supabase/auth.ts` provide type-safe auth methods.
- [ ] TypeScript check and build pass cleanly.
