## Objective

Design the end-to-end authentication and session lifecycle architecture for Zankai Orbit, defining shared TypeScript contracts, auth states, cookie refresh mechanisms using `@supabase/ssr`, store cleanup/hydration rules, and recording the decision in `ADR-002`.

## Requirements

1. **Session Lifecycle States (`src/types/orbit.ts` or `src/types/auth.ts`):**
   - Define type-safe user session states: `unauthenticated`, `authenticating`, `authenticated`, `offline_preview`.
   - Define auth payload interfaces for email magic link, passwordless login, and OAuth provider sign-in.
   - Define user profile representation and tier permissions.
2. **SSR Cookie & Middleware Strategy:**
   - Specify how Next.js App Router middleware interacts with `@supabase/ssr` cookies.
   - Define route protection: public marketing/preview paths vs authenticated data endpoints.
3. **Client State Lifecycle:**
   - Define rules for store hydration on sign-in (fetching user's boards from Supabase).
   - Define rules for store purge on sign-out (clearing tasks, timer, and detail drawer back to clean preview state).
4. **Architectural Decision Record (`.team/decisions/ADR-002-auth-session-lifecycle.md`):**
   - Context, options considered (NextAuth / Supabase Auth / Clerk), decision rationale (Supabase Auth native to RLS), and consequences.
5. **Verification:**
   - Run `npx tsc --noEmit` to verify type contracts.
   - Run `npm run build` to confirm compilation.
